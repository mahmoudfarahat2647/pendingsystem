# Arabic (AR) Language — i18n

Epic: `#300` — Arabic language for the Sidebar, Notifications, Settings and action modals. The layout stays LTR.

| Wave | Issue | Scope |
|---|---|---|
| 1 | `#301` | Foundation: dictionaries, `translate`, `useT`, `LocalizedScope`, Arabic font, persisted `language`, EN\|AR toggle in the Settings header |
| 2 | `#302` | Sidebar (nav, user menu, Unsaved Changes dialog) |
| 3 | `#303` | Notifications dropdown (notifications carry `titleKey`/`descriptionKey`/`params`) |
| 4 | `#304` | Settings modal (statuses, theme, backup & reports, permission tabs) |
| 5 | `#305` | Action pop-up modals (this page's final wave) |

## Design

- **Text-only translation.** `<html lang="en">` never changes and there is no global `dir`. Only translated leaf text gets `lang="ar" dir="rtl"` and the `font-arabic` class (IBM Plex Sans Arabic, loaded in `src/app/layout.tsx`), via `LocalizedScope` (`src/components/shared/LocalizedScope.tsx`). Button order, icon placement and dialog layout are identical in both languages.
- **Language state.** `language: "en" | "ar"` in the Zustand `uiSlice`, persisted with the rest of the UI preferences. Old snapshots without the field fall back to `"en"`.
- **Dictionaries.** `src/i18n/dictionaries/en.ts` is the source of truth. `ar.ts` is typed as `Dictionary` (the deep-string shape of `en`), so a missing or extra key fails `pnpm run type-check`. `src/test/i18n/dictionaries.parity.test.ts` also checks key parity and non-empty strings at runtime.
- **Lookup.** `translate(lang, key, params)` in `src/lib/i18n/translate.ts` is pure: dot-path lookup, `{param}` interpolation, falls back to English then to the key. React code uses `useT()` → `{ t, lang, dir, scopeProps }`.

## Usage pattern

```tsx
const { t, lang } = useT();

<DialogTitle>
	<LocalizedScope lang={lang}>{t("modals.freeze.title")}</LocalizedScope>
</DialogTitle>
<Textarea placeholder={t("modals.freeze.reasonPlaceholder")} />
```

- Wrap text, never flex/grid containers.
- Attributes (`placeholder`, `title`, `aria-label`, `sr-only` text) take `t(...)` directly.
- Callers that pass strings into a shared component (e.g. `ConfirmDialog` title/description, `ReorderReasonDialog` placeholder/helperText/srDescription) translate at the call site with their own `useT()`; the shared component itself wraps whatever it receives in `LocalizedScope`.
- A component that needs a translation key *plus* interpolation params to pick between variants (e.g. `UnfreezeMoveDialog`'s per-origin message) returns `{ key: TranslationKey, params?: TranslationParams }` from a small pure helper and calls `t(key, params)` at render time, rather than returning a pre-rendered string.
- `ConfirmDialog`'s `confirmText`/`cancelText` props are now optional and fall back to `common.confirm`/`common.cancel` inside the component when a caller omits them.

## Translation rules

- Sidebar navigation labels and their collapsed tooltips are translated in AR (e.g. `Orders` → `الطلبات`); their routes, order, icons and left-side layout are unchanged. The `BODY&PAINT` brand name stays as written.
- Stage names stay English inside modal copy and stage pickers, e.g. `إفراج إلى Call List`, `قادم من Main Sheet`.
- User content is never translated: notes, reason text, reminder subjects, quick-template text, links, file names, VINs, part numbers.
- Toasts stay English, **except** the "Move to Main Sheet" toolbar button, its confirmation dialog, and its success/partial/failure/permission-off toasts (`modals.moveToMain.*`, issue `#314`) — a narrow, explicit exception, not a change to the general rule.
- Western digits `0–9`; existing date/time formats.
- Guard words stay English: the release word `release`, and ConfirmDialog type-to-confirm words (e.g. `yes` on "Commit to Main Sheet").

## Wave 5 — action modals

Namespace `modals.*` (`shared`, `confirm`, `stageConfirm`, `freeze`, `archive`, `reorder`, `release`, `unfreeze`, `duplicate`, `note`, `reminder`, `attachment`, `moveToMain`).

| Modal | Notes |
|---|---|
| `ConfirmDialog` | Default Confirm/Cancel come from `common.*` when a caller omits `confirmText`/`cancelText`. Type-to-confirm instructions translated; the word and its matching are unchanged. Callers — Orders, Main Sheet, Call List, Booking, Archive pages and `SearchResultsView` — pass `modals.stageConfirm.*` titles/descriptions (with `{count}` interpolation for selection counts) and `modals.stageConfirm.commit*` for the Orders "Commit to Main Sheet" dialog. |
| `FreezeReasonModal` / `ArchiveReasonModal` | Reason is still required (confirm disabled while blank). Quick-template text shows as typed. Shared `modals.shared.quickTemplates` / `modals.shared.newTemplatePlaceholder` keys are reused by both. |
| `ReorderReasonDialog` | Title/label/buttons translated; page callers pass translated placeholder/helper/sr text (`modals.reorder.placeholderMainSheet` / `placeholderArchive` / `placeholderWrongPart`, `modals.reorder.helperBackToOrders`, `modals.reorder.srDescription`). |
| `ReleaseConfirmationModal` | Copy translated, including the mileage value (`modals.release.mileageValue`, `{mileage}` interpolation); `RELEASE_CONFIRMATION_WORD` and its trimmed, case-insensitive match untouched. |
| `UnfreezeMoveDialog` | Title (`moveOne`/`moveMany`), description, origin message (`originSingle`/`originMixed`/`originPartial`/`originNone`, via a typed `{key, params}` helper) and aria-label translated. Stage names in the picker and the "Freeze" label stay English. |
| `DuplicateOrderWarningModal` | Sentence split around the VIN and part number spans (`descriptionBeforeVin` / `descriptionBeforePart` / `descriptionAfter`). |
| `EditNoteModal` / `EditReminderModal` | All labels, placeholders, the history-unlock and clear-reminder confirmations. The reminder "must be in the future" message is a toast and stays English. |
| `EditAttachmentModal` | Inline validation errors are stored as a `TranslationKey` (not a pre-rendered string), so they follow a language switch. Upload/save failure toasts stay English. |

### Review follow-ups (PR #313)

- **Close button label:** Release, Freeze, Archive, Reorder, Unfreeze, Duplicate, Note and Reminder dialogs pass `closeLabel={t("common.close")}` to `DialogContent`, so screen readers announce `إغلاق` in AR. `ConfirmDialog` and `EditAttachmentModal` use `hideClose` (the attachment modal's own close button already uses `modals.attachment.close`).
- **Reminder date picker:** `DateTimePicker` takes an optional `lang` (default `"en"`). In AR it formats the trigger date and the calendar (month caption, weekdays, next/previous labels) with the `react-day-picker/locale` `ar` locale, forces `numerals="latn"`, and pins `weekStartsOn={0}` so the grid keeps the English Sunday-first layout. The "Pick a date" fallback and AM/PM display text are translated; the stored date/time and the `AM`/`PM` select values are unchanged. New dictionary keys: `common.close`, `modals.reminder.pickDate`, `modals.reminder.am`, `modals.reminder.pm` (EN and AR).

### Move to Main Sheet exception (issue `#314`)

The `modals.moveToMain.*` namespace (`action`, `notEligible`, `permissionOff`, `success`, `partial`, `noneMoved`, `failed`) covers the shared `MoveToMainButton` (`src/components/shared/MoveToMainButton.tsx`) and `MoveToMainConfirmDialog` (`src/components/shared/MoveToMainConfirmDialog.tsx`), plus the success toast from the Call List/Booking/Archive `use*PageActions.ts` hooks and the success/partial/none-moved/failed/permission-off toasts from `useSearchResultsActions.ts` and `MoveToMainConfirmDialog`. `MoveToMainConfirmDialog` itself renders a plain `ConfirmDialog` with `modals.stageConfirm.moveToMain*` title/description/Yes/No text (added with this feature) and adds the permission re-check toast on top.

This is the one place a **toolbar button** and its **toasts** are translated — everywhere else, toolbars and toasts stay English per the rules above. The button's `aria-label` takes `t(...)` and its tooltip text renders inside `LocalizedScope`, as does the confirmation dialog's text, so both follow the language switch (covered by `src/test/MoveToMain.test.tsx`).

## Out of scope

Grids, page toolbars, the Header, global search, booking calendars and the order form stay English, **except** the "Move to Main Sheet" button and dialog described above (issue `#314`), which is translated wherever it appears — the Call List, Booking and Archive toolbars and the Global Search toolbar (it is never shown on Orders, Main Sheet or Freeze).
