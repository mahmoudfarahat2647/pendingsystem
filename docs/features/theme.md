# Theme (Dark / White)

Two themes: **Dark** (the original, default) and **White**. Spec: `.github/specs/white-theme.md` (issue `#340`, tracking `#352`).

## How it works

- **Preference**: browser-local key `pending-sys-theme`, values `dark` | `white`. A missing, unreadable or unrecognised value, or storage that throws, resolves to Dark. It is deliberately **not** in the persisted Zustand store (that hydrates after first render and would flash the wrong theme).
- **Applied via the `dark` class on `<html>`**. Dark = class present. White = class absent, so the light tokens already defined in `:root` (`globals.css`) apply.
- **Arabic typography**: `font-arabic` uses the bundled IBM Plex Sans Arabic 400/500/700 WOFF2 files through `next/font/local`. Builds do not need to fetch this font from Google Fonts.
- **No flash**: `src/app/layout.tsx` keeps `class="dark"` as the SSR default and injects `THEME_INIT_SCRIPT` (`src/lib/theme.ts`) in `<head>`, which removes the class before first paint only for a saved `white` choice. It also applies on the login / forgot-password / reset-password pages.
- **Live switching, no remount**: `useTheme()` (`src/hooks/useTheme.ts`, `useSyncExternalStore`) writes the key and toggles the class in place. Routes, draft sessions, forms, selections, scroll position and open dialogs are untouched. Cross-tab changes sync via the `storage` event, handled by **one shared window listener** (added when the first subscriber mounts, removed when the last unmounts) rather than one per subscriber, since grid cells can mount hundreds of subscribers.
- **Storage that cannot be written**: `writeTheme` (`src/lib/theme.ts`) returns `false` when storage is blocked or full (private mode, blocked site data, quota). `setTheme` then keeps the choice in a module-level in-memory `unsavedTheme`, so the `<html>` class and the hook snapshot never disagree (grids, charts and toasts follow the new theme). `getCurrentTheme()` (exported from `useTheme.ts`) returns the unsaved in-memory choice if present, otherwise `readTheme()`; the next cross-tab `storage` event for the theme key clears it. `ForceDarkTheme` restores the theme through `getCurrentTheme()` when leaving an always-dark route.
- **Settings → Theme tab** (`ThemeTab.tsx`): a card picker (`ThemeToggle` in `src/components/ui/theme-toggle.tsx`, previews in `theme-previews.tsx`) showing a miniature app mock-up (sidebar + content, drawn as an SVG with a per-theme palette) per theme with a label pill, yellow ring and sliding underline (`motion/react`) on the selected card. The picker is a `role="radiogroup"` (labelled with the tab title) of native radio inputs, so it stays keyboard- and screen-reader-accessible. The cards are listed White first, then Dark, side by side from the `sm` breakpoint, inside a bordered panel that holds the tab title/description above a divider. Explicit Dark / White only, translated EN/AR under `settings.theme.*` (the label pills are wrapped in `LocalizedScope`). No system-theme option and no header control (per spec). Render/behavior test: `src/test/ThemeTab.test.tsx` (Dark selected by default; selecting a card saves the theme and updates `<html>` in place).
- **`/mobile-order` is always Dark**: the pre-paint script skips it (direct load), `ForceDarkTheme` in its layout forces Dark on client navigation and restores the current theme on leave, and the cross-tab handler and `ThemedToaster` ignore the preference on always-dark paths (`isAlwaysDarkPath`).
- **Sonner toasts** follow the theme (`ThemedToaster`).
- **AG Grid**: `gridThemeDark` (unchanged) and `gridThemeWhite` in `src/lib/ag-grid-setup.ts`; `getGridTheme(theme)` is passed as the `theme` prop of `DataGrid` and `SearchResultsGrid`, so switching never remounts the grid.
- **Hook tests** (`src/test/useTheme.test.tsx`): the chosen theme survives a throwing `setItem`, and only a single `storage` listener is installed however many components subscribe.

## The Dark-safety rule (how new UI must be written)

Dark output is the reference and must not change.

- Hardcoded dark colours keep their **original value verbatim under `dark:`**; the White value is the default: `bg-[#0c0c0e]` becomes `bg-white dark:bg-[#0c0c0e]`.
- Existing `dark:` variants are audited (removing the `dark` class activates their non-dark side).
- No unconditional edit to a shared primitive or global rule. White-only global CSS is scoped, e.g. `:root:not(.dark) ::-webkit-scrollbar-thumb`.
- Prefer CSS/Tailwind variants over reading the theme in JS for cell renderers: grid cells can mount in the hundreds, so avoid `useTheme()` there (see `StatusRenderer` and `CntrRdgCellRenderer` below).
- `text-white` on a coloured button (`bg-red-500`, `bg-indigo-600`, ...) stays `text-white` in both themes.
- Do not add `dark:bg-*` next to a `className` that callers override with their own `bg-*` (it would win in Dark).
- Guard: `src/test/whiteThemeDarkSafety.test.ts` scans all of `src` (`.ts` and `.tsx`, excluding `test`) and fails if a bare dark-only colour literal (for example `bg-[#1c1c1e]`, `border-white/10`, `text-gray-100`, `text-gray-200`) reappears. The scan matches the literal as a whole class token **with or without a variant chain** (`hover:`, `group-hover:`, `[&_select]:`, ...); a chain is only allowed when it contains `dark:`, which is where Dark values are kept verbatim. A small `ALLOWED_TOKENS` set holds exact tokens that are intentional White values (currently `placeholder:text-slate-400`). A separate case ("dark-safety guard catches variant-prefixed leaks") proves the matcher flags `hover:`/`group-hover:`/arbitrary-variant leaks and allows `dark:` chains. Exempt from the scan: `Sidebar.tsx` (its own charcoal White design, protected by a dedicated test instead, see below), `global-error.tsx`, `useDraftSession.tsx` (self-contained dark recovery toast), `/mobile-order`. The auth components (`src/components/auth/`) are no longer exempt; they are converted and scanned like the rest of `src`. The same test also has a "grid cell contrast" case (see below) that checks the `--grid-positive` variable and that the green cell files no longer use a bare `color: "#22c55e"`.
- **Sidebar guard**: a "Sidebar White redesign keeps Dark verbatim" case in the same test asserts that the original Dark container and active-tab classes are still present under `dark:` (`dark:bg-black/80`, `dark:bg-renault-yellow`, `dark:text-black`, `dark:font-bold`, `dark:shadow-[0_0_20px_rgba(255,204,0,0.2)]`, `dark:rounded-none`, `dark:border-r`), and that the charcoal rounded shell (`bg-[#1f2328]`, `rounded-r-[28px]`), the soft yellow tint (`bg-renault-yellow/10`) and the accent pill (`bg-renault-yellow dark:hidden`) exist for White.
- **Dashboard hero guard**: the converted-shell case in the same test asserts that the dashboard page keeps both hero images (`bg-[url('/hero.png')]` and `dark:bg-[url('/dashboard-car.webp')]`), uses the shared fixed ` h-[460px] ` frame for both themes, no longer contains the old `aspect-[2027/776]` ratio, and keeps `dark:bg-cover dark:bg-center` for Dark.

## White design notes

- **Sidebar**: Dark is unchanged (black, full-yellow active tab). White uses a charcoal `#1f2328` panel with rounded right corners (28px, no right border, `overflow-hidden`), light-gray labels, and a minimal active tab: soft yellow tint, thin inset yellow outline, white semibold label, yellow icon, a tinted yellow count badge, and a small yellow accent pill on the left edge (`dark:hidden`). The logo divider and the user-profile strip are transparent in White, and the online-dot border matches the charcoal panel. All Dark classes stay verbatim under `dark:` (`dark:rounded-none`, `dark:bg-renault-yellow`, ...). Header, dropdowns, dialogs and overlays are light (overlay dim is lighter in White).
- **Dashboard**: the hero is a single fixed `h-[460px]` frame in both themes (the White-only `aspect-[2027/776]` ratio was removed), so the dashboard fits one screen without scrolling in both themes. White uses `public/hero.png` on a `#eceef1` frame background, scaled to the frame width and anchored to the top without repeating (`bg-[length:100%_auto] bg-top bg-no-repeat`), so all the baked-in copy (left heading and right "Excellence in every finish") stays visible at every desktop width; on narrower frames the image is shorter than 460px and the light `#eceef1` band shows below it, mostly behind the stat tiles. Dark keeps `/dashboard-car.webp` with `bg-cover bg-center` under `dark:` and its `dark:bg-black` frame. White and Dark have identical page height (verified at 1672×941: no scroll). Stat tiles and the calendar are non-interactive in White (no arrow icon, no pointer cursor, no hover). Charts read the theme: ring track, tooltip, bar value labels (White only), no drop shadow in White.
- **Status colours** (`StatusRenderer`): stored colours are never modified. A custom CSS colour is passed to the cell as the `--status-color` custom property on a `.status-chip` span (no `useTheme()` in the renderer). `globals.css` defines `.status-chip { color: var(--status-color) }` for the plain coloured text in Dark, and `:root:not(.dark) .status-chip` for the White tinted chip (darker text via `color-mix`, tinted background and border, 4px radius). Non-CSS colours keep the gray text classes. The Reorder status text is `#a16207` in White and keeps `#d4a017` under `dark:`. Test: `src/test/StatusRenderer.theme.test.tsx` (checks the class and custom property, and that the White chip is scoped to `:root:not(.dark)` in `globals.css`).
- **Grid cell contrast**: the green "positive" cell colour (mobile numbers, Booking date, Global Search "Booking" source, Archive cells) is written as `var(--grid-positive, #22c55e)`. `globals.css` defines `--grid-positive: #15803d` only under `:root:not(.dark)`, so White gets a darker green while Dark, where the variable is unset, falls back to the original `#22c55e`. Used in `GridConfig.tsx` (Booking date, Call-list mobile, Global Search source), `MobileCellRenderer.tsx` and `archive/page.tsx`. The CNTR RDG alert icon (`CntrRdgCellRenderer`) draws in `currentColor` inside a span with Tailwind classes: `text-[#dc2626] dark:text-[#ef4444]` for high and `text-[#a16207] dark:text-[#eab308]` for warning, so White uses darker shades and Dark keeps `#ef4444` / `#eab308` (no `useTheme()` in the renderer).
- **Accent text** (`text-indigo-400`, `text-red-400`, ...) becomes the `-600` shade in White for contrast.
- **Focus accent**: `--champagne` is defined in the light `:root` (`42 45% 40%`) as the White focus accent; `.dark` redefines it with the original value.
- **Contrast fixes in shared pieces**: booking calendar out-of-month days (`text-gray-300 dark:text-gray-800`), booking task hover text, the `DateTimePicker` trigger hover, the Settings statuses "editors locked" pill (`bg-white/90` with `text-gray-700` in White), and `SimpleDatePicker` (`[color-scheme:light] dark:[color-scheme:dark]`, with the month/year dropdown selects light in White and the original dark values under `dark:`).
- **Auth pages** (`AuthPageShell`, `LoginForm`, `ForgotPasswordForm`, `ResetPasswordForm`): full-bleed photo `public/login-background-canyon.webp` (served at `quality={90}`, allowed by `images.qualities: [75, 90]` in `next.config.ts`) behind a compact 340px glass card (`backdrop-blur-md`; `bg-white/40` in White, `dark:bg-black/20` in Dark). Two light fades keep the photo vivid: a left-edge fade behind the card (`from-white/40` / `dark:from-black/35`) and a bottom fade behind the "pending system" footer (`from-white/50` / `dark:from-black/40`). The card has a small left-aligned "Eim" mark with a `#FFCC00` underline, an optional title/subtitle (login uses "Welcome back" / "Sign in to your workspace."), visible `<label>`s above translucent 40px inputs, a rounded yellow submit button and a muted link. The shared field classes live in `src/components/auth/authStyles.ts`. Text is black in White and white in Dark. Error, alert and success text use darker White shades (`red-600`, `amber-700`, `green-700`) with the `-400` shades under `dark:`. The "pending system" `ShiningText` uses a grey-to-black shine gradient with no text-shadow in White (grey-to-white with the original shadow in Dark).

## Known gaps / follow-ups

- Remaining inline gray grid cell colours (`#6b7280`, about 4.8:1 on white) are left as is; the Archive source cell is intentionally dimmed to 50% opacity. The faint green cells were addressed via `--grid-positive`.
- `global-error.tsx` and the draft-recovery toast stay dark by design.
- No automated pixel comparison exists (the earlier screenshot-baseline tool, PR `#351`, was dropped); Dark is protected by the guard test above and a manual check on each preview.
